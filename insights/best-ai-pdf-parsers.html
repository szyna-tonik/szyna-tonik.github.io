If you have ever fed a PDF to a parser and got back a table with its columns shuffled, or a two-column page read straight across, you already know why this list exists. A PDF stores glyphs at coordinates, not sentences, and reading one is a reconstruction problem. The AI PDF parsers below solve it to different degrees, at different prices, on different hardware.

By AI PDF parser we mean a tool that uses a layout model, a language model or a vision model to rebuild the page, rather than a library that only reads the text layer; two such libraries are here because they are the right answer for clean files.

This guide is for the developer who has to pick one: you are building retrieval, an agent, a search index or an extraction pipeline, and the parser decides what your model sees.

We rank nine tools across four kinds, one agentic parser, three open-source AI parsers, two Python libraries and three cloud document platforms, and say which to use when. LlamaParse is our pick where output quality on hard documents decides the project; Docling, Marker and MinerU are the open-source choices; PyMuPDF and pdfplumber are the right call when the PDFs are clean and the budget is zero; Azure, Google and Textract win when you are already on that cloud.

How we chose these nine

The shortlist came from where developers actually look: the first page of results for this query, the r/LocalLLaMA and r/dataengineering threads on PDF parsing, and the tools the AI Overview names. A tool stayed on the list if it has a current release, a license we could read, and either a public benchmark or a pricing page we could cite; if it returns structure rather than raw text, or is the library developers reach for when raw text is enough; and if it adds a real choice rather than a second version of one already here.

That left nine: one agentic parser, three open-source AI parsers, two Python libraries and three cloud document platforms.

Hosted parsers we have not run on our own documents, such as Unstructured, Reducto and Firecrawl, are not ranked here. Prices are US list as of October 21, 2026 and move often; treat them as a starting point for your own estimate.

1. LlamaParse

LlamaParse is the one tool on this list built around what happens after the page is read; LlamaIndex calls the approach agentic document parsing. Instead of one model reading the whole page, a layout model segments it, an orchestrator sends each region to the right OCR model, LLM or vision-language model, and validation passes check the result before it is assembled into Markdown, JSON or spatial text. Tables come back as tables with cell geometry, two-column pages come back in reading order, and charts come back as data rather than a picture caption. The same product does schema-based extraction: hand it a JSON schema and it returns typed fields with per-field confidence and a citation to the page region each one came from.

It leads this list because it is the only tool here that was built for the moment after parsing: what an agent or a retriever does with the output. On ParseBench (April 2026, about 2,000 human-verified enterprise pages), the Agentic tier scored 84.9% overall, the top result, and was the only method competitive across all five dimensions measured. With OCRia-1, the vision-language model LlamaIndex released on October 22, 2026, the ParseBench score is 87.4, with 91.5 on tables and 85.1 on charts; the next-best parsing model scores 75.3.

Strengths

  • Four parsing tiers at 1, 3, 10 and 45 credits a page (Fast, Cost Effective, Agentic, Agentic Plus), plus a Cost Optimizer that sends only the hard pages of a file to the expensive tier.
  • Layout-aware output in three shapes: Markdown with headings and tables, JSON with page geometry and bounding boxes, and spatial text that keeps column alignment.
  • Natural-language parsing instructions, so "treat footnotes as part of the paragraph above" is a parameter, not post-processing code.
  • Broad input support beyond PDF: Word, PowerPoint, spreadsheets, HTML and images, with a spreadsheet mode for messy XLSX files. The supported file types entry has the full list.

Trade-offs

  • It is a hosted API. Standard plans process documents in LlamaIndex's cloud; teams with data-residency rules need the Enterprise plan's private VPC deployment or an open-source parser from this list.
  • Agentic Plus costs 45 credits a page. Pin a tier and a dated version in production and let the Cost Optimizer keep clean pages on the cheap tier.
  • If every PDF you have is digital-native text with no tables, a library like PyMuPDF is faster and free. LlamaParse earns its price on the documents that break libraries.

Output, integration and cost

  • Output: Markdown, plain or spatial text, JSON with bounding boxes, or typed JSON matching your schema.
  • Integration: REST API with Python, TypeScript and .NET SDKs, a web playground, an n8n node and an MCP server for agents. Results are cached for 48 hours, so re-parsing the same file is free.
  • Cost: 1,000 credits cost $1.25. At 10 credits a page, Agentic is about 1.25 cents a page; Fast is $1.25 per 1,000 pages. The free plan includes 10,000 credits a month.

2. Docling

Docling is IBM's open-source document conversion toolkit and the open-source parser most often recommended in the r/LocalLLaMA and r/dataengineering threads this year. It runs a layout model and a table-structure model locally, with pluggable OCR engines such as Tesseract and RapidOCR for scanned pages, and returns a lossless JSON document that it can render as Markdown, HTML or DocTags. Everything runs on your machine, which is why it comes up first whenever someone asks for a parser that can run air-gapped.

Its range is unusual: PDF, Office formats, EPUB, LaTeX, images, email, and audio and video through a transcription pipeline. For a team that wants one local converter for every file type in a shared drive, that breadth is the selling point. For a team that only has hard PDFs, the question is accuracy on those pages, and there Docling is solid rather than best in class: on Datalab's published olmOCR-Bench run it scored 50.3 overall against 76.0 for Marker, with the caveat that a competitor published those numbers.

Strengths

  • MIT license, 69,000 GitHub stars and a release every few days (v2.140.0 on October 16, 2026), so it is maintained and safe to depend on commercially.
  • Lossless JSON as the native format, with Markdown, HTML and chunked JSONL rendered from it, so chunking and provenance are first-class.
  • Local execution on CPU; first run downloads roughly 1 to 2 GB of model weights.

Trade-offs

  • CPU-only parsing of long scanned PDFs is slow; a GPU or a batch queue is the realistic setup at volume.
  • Table structure on dense financial pages and reading order on complex layouts trail the hosted agentic parsers, so benchmark your own pages before standardizing.
  • No confidence scores or field-level citations; validation is your job downstream.

Output, integration and cost

  • Output: Markdown, HTML, DocTags, lossless JSON, text, chunked JSONL.
  • Integration: Python library and CLI, with a Docling Serve API for self-hosting.
  • Cost: free. Budget for a GPU and for the person who runs it.

3. Marker

Marker (the marker-pdf package from Datalab) converts PDFs, images and Office files to Markdown, JSON or HTML, and is the open-source parser to pick when speed on a GPU matters. It runs a pipeline of layout, OCR and equation models, keeps LaTeX for formulas, extracts images and formats tables, and has a "balanced" mode for GPUs and a "fast" mode for CPU or Apple Silicon. Version 2.0.0 shipped on July 20, 2026.

Datalab publishes its own olmOCR-Bench results: Marker balanced at 76.0 overall and 2.9 pages a second on a B200, ahead of MinerU's pipeline at 72.7 and Docling at 50.3. The license is the catch. The code is Apache 2.0, but the model weights are under a modified OpenRAIL-M license that is free only for research, personal use and companies under $5 million in funding or revenue; above that you need a commercial arrangement. Datalab also sells the same stack as a hosted API, so a team that outgrows self-hosting has a path.

Strengths

  • Fastest of the open-source AI parsers on a GPU, with a CPU mode that skips OCR for digital-native PDFs.
  • Equation and figure handling aimed at scientific papers, with LaTeX preserved in the Markdown.
  • Hosted option: Datalab's Convert API is $4 per 1,000 pages on the fast and balanced modes and $10 on accurate, with a $20 monthly free allowance on a work email.

Trade-offs

  • Weights license needs legal review once your company passes the $5 million threshold.
  • CPU processing gets slow past about 20 pages per document, by the project's own account.
  • No schema extraction or confidence scoring; it is a converter, not an extraction system.

Output, integration and cost

  • Output: Markdown, JSON, HTML, chunks, with images extracted alongside.
  • Integration: Python library and CLI; a server mode runs on vLLM (NVIDIA) or llama.cpp (CPU and Apple Silicon).
  • Cost: free to self-host under the license thresholds; $4 to $10 per 1,000 pages hosted.

4. MinerU

MinerU, from OpenDataLab at Shanghai AI Lab, is the parser that academic and technical teams reach for. It was designed around scientific papers, so multi-column layouts, formulas, footnotes and mixed Chinese and English text are its home ground. MinerU 4.0 (4.0.12 on PyPI, October 11, 2026) runs its models on CPU by default (ONNX, with the vision-language model on llama.cpp) and has an NVIDIA build for throughput, and can render the same parse as Markdown, HTML, LaTeX, DOCX or structured JSON.

With 81,000 GitHub stars it is the most-starred project here, and the MinerU2.5-Pro paper (April 2026) documents the model behind it. The trade-offs are practical: the license is Apache 2.0 with added conditions that you should read before shipping it in a product, and the pipeline is heavier than Marker's for equivalent accuracy on Datalab's benchmark.

Strengths

  • Formula and LaTeX extraction, multi-column reading order and table recognition tuned on papers.
  • Nine output renderers from one parse, including DOCX and EPUB, which no other tool on this list offers.
  • Runs on CPU by default; the GPU build needs 8 GB of VRAM and 16 GB of RAM.

Trade-offs

  • Custom license terms rather than plain Apache 2.0 or MIT.
  • Slower per page than Marker on a GPU (0.54 pages a second against 2.9 in Datalab's run).
  • Business documents such as invoices and forms are not its focus; the cloud platforms and LlamaParse do better there.

Output, integration and cost

  • Output: Markdown, HTML, LaTeX, DOCX, EPUB, PDF, structured content lists.
  • Integration: Python package, CLI and a local API; a Gradio web UI for testing.
  • Cost: free under the MinerU open-source license.

5. PyMuPDF

PyMuPDF is the fastest way to get text out of a digital-native PDF in Python, and PyMuPDF 2.0 (October 19, 2026) is the current major release. Artifex's own timing on 7,031 pages puts text extraction at 8 seconds against 227 for pdfminer. There is no layout model: it reads the text layer, finds tables heuristically with find_tables(), renders pages to images, and can call Tesseract for scanned pages. PyMuPDF4LLM, the companion package, turns that into Markdown or JSON with headings, tables and page chunks and needs no GPU.

That makes it the right first tool for clean PDFs, and the wrong last tool for hard ones. On a scanned annual report or a form with nested tables it will return text in the wrong order and tables as prose, because there is no model to tell it what a table is. The other thing to check is the license: PyMuPDF is AGPL, which means a commercial product that embeds it either open-sources its code or buys a commercial license from Artifex.

Strengths

  • Speed and zero infrastructure: a pip install, no model downloads, no GPU.
  • Full PDF toolkit in one library: rendering, images, annotations, redaction, form fields, and Markdown via PyMuPDF4LLM.
  • Reads PDF, XPS, EPUB, images and (converted) Office files; v1.28 added table-detection options and a Pyodide wheel for the browser.

Trade-offs

  • No layout understanding. Multi-column pages, scanned documents and complex tables need a model-based parser.
  • AGPL licensing for closed-source commercial use, unless you pay for the commercial license.
  • OCR through Tesseract is bolt-on; accuracy on scans is Tesseract's, not PyMuPDF's.

Output, integration and cost

  • Output: text, Markdown, JSON, SVG, images, PDF.
  • Integration: Python package; PyMuPDF4LLM has native readers for the major document pipelines.
  • Cost: free under AGPL; commercial license priced by Artifex.

6. pdfplumber

pdfplumber sits on pdfminer.six and gives you every character, line and rectangle on a page with its coordinates. That is a different job from the AI parsers above: you are not asking it to understand the page, you are writing the rules yourself. For a fixed-layout statement or a form your own system generates, that control is exactly what you want, and its table extraction (rebuilt in v0.5.0, current release 0.11.10 from June 15, 2026) handles ruled tables well.

It has no OCR, no layout model and no Markdown output, and it is slower than PyMuPDF. It is here because developers keep choosing it for the right reasons: a 10,700-star MIT library that lets you debug a table visually and extract it deterministically is worth more than a model when the layout never changes.

Strengths

  • Character-level coordinates and a visual debugger, so you can see why a table came out the way it did.
  • Deterministic, rule-based table extraction for ruled or consistently aligned tables.
  • MIT license and no dependencies beyond pdfminer.six.

Trade-offs

  • Machine-generated PDFs only; the project itself says it works best on those rather than scans.
  • Tables without rules or with merged cells need hand-written settings, and every new layout means new code.
  • Slower than PyMuPDF by a wide margin on large files.

Output, integration and cost

  • Output: text, tables as lists, per-object coordinates, page images.
  • Integration: Python package.
  • Cost: free.

7. Azure AI Document Intelligence

Of the three cloud platforms, Azure's is the friendliest to AI pipelines because its Layout model (API v4.0) returns Markdown directly, with section hierarchy, paragraph roles such as title, section heading, footnote and page footer, figures as cropped images, and tables rendered as HTML so merged cells survive. Add the prebuilt models for invoices, receipts, IDs and tax forms, custom extraction models, and Read and Layout containers that run inside your own network, and it covers more of the stack than Google or AWS.

What it does not do is reason about a page. Markdown from Layout is a faithful transcription of what the layout model saw; a chart is a figure with a caption, not data, and there is no tier that routes hard pages to a stronger model. Pricing is per page per model, and the public page currently shows placeholders in some regions, so confirm your region's rate before budgeting.

Strengths

  • Markdown output with sections, roles, figures and HTML tables, which drops straight into a chunking step.
  • Containers for Read (June 2025) and Layout (April 2025) when documents cannot leave your network.
  • Prebuilt models for business documents and new tax models (March 2026); nine handwriting languages.

Trade-offs

  • Markdown is a transcription, not an interpretation; charts and figures stay images.
  • Each model is priced separately, so a Layout plus Invoice pipeline pays twice per page.
  • Regional price placeholders on the public pricing page; confirm before you forecast.

Output, integration and cost

  • Output: JSON with pages, paragraphs, tables, figures and sections; Markdown on request.
  • Integration: REST and SDKs for Python, .NET, Java and JavaScript; Document Intelligence Studio for testing.
  • Cost: Read $1.50 and Layout $10 per 1,000 pages at US list, carried from earlier verification; 500 free pages a month on the F0 tier.

8. Google Document AI

Google Document AI is a catalog of processors, and two matter for PDF parsing. Enterprise Document OCR reads printed and handwritten text in more than 200 languages, the widest list here. The Layout Parser combines that OCR with Gemini to return a document tree of headings, paragraphs, tables and figures, and then produces context-aware chunks that carry their ancestral headings and table headers, which is the exact shape a retriever wants. Preview versions run on Gemini 2.5 and 3.0 models and add text descriptions of figures and charts.

The limits are worth knowing before you design around it: online Layout Parser requests cap at 15 PDF pages and 20 MB, so anything bigger goes through batch, and the Gemini-based preview versions use a global endpoint that is not data-residency compliant. Google is also the most GCP-shaped of the three platforms; it is at its best when documents already sit in Cloud Storage and the index lives in Vertex AI.

Strengths

  • Layout Parser returns chunks with headings attached, so you can skip your own chunker.
  • More than 200 OCR languages, including handwriting.
  • Custom Extractor runs on Gemini and can be fine-tuned on your own documents; release notes dated September 21, July 17 and May 27, 2026 show the catalog still moving.

Trade-offs

  • 15-page and 20 MB online limits for Layout Parser; use batch for real documents.
  • Multi-page tables can split in two, and nested tables in DOCX are not supported.
  • Layout Parser is $10 per 1,000 pages, nearly seven times the plain OCR rate.

Output, integration and cost

  • Output: JSON document tree and chunks; Enterprise Document OCR returns text with layout blocks.
  • Integration: REST and client libraries; batch jobs read and write Cloud Storage.
  • Cost: Enterprise Document OCR $1.50 per 1,000 pages to 5 million then $0.60; Layout Parser $10; Custom Extractor $30 then $20.

9. Amazon Textract

Amazon Textract is the oldest of the three and still the most form-oriented. Detect Document Text reads printed and handwritten text; Analyze Document adds Forms (key-value pairs), Tables, Queries (ask a question of the page) and Signatures; Analyze Expense handles invoices and receipts. A Layout feature, free when combined with Tables, tags titles, section headers, lists, figures and page numbers in reading order. A model update on June 30, 2025 improved text and table accuracy across the board.

The output is Textract's weakness for AI pipelines. Everything comes back as JSON blocks with IDs and relationships, and turning that into Markdown means either the open-source Textractor library's linearization helpers or your own walk over the layout blocks. Pricing stacks by feature, so a Forms plus Tables call is $65 per 1,000 pages, which is more than the Agentic tier of LlamaParse at $12.50.

Strengths

  • Best-in-class form and key-value extraction among the clouds, plus Queries for ad-hoc questions.
  • Native fit with S3, Lambda and Step Functions for event-driven pipelines.
  • Generous free tier for text: 1,000 pages a month for three months.

Trade-offs

  • No Markdown output; JSON blocks need linearizing before chunking.
  • Feature pricing adds up: Forms is $50 per 1,000 pages on its own.
  • Six printed languages for OCR, the shortest list here; no charts, no equations.

Output, integration and cost

  • Output: JSON blocks (text, forms, tables, layout, signatures, expense fields).
  • Integration: AWS SDKs, async jobs for multi-page PDFs, Textractor for post-processing.
  • Cost (US West, first million pages): text $1.50, Tables $15, Queries $15, Forms $50, Signatures $3.50, Analyze Expense $10 per 1,000 pages.

How to choose

Start from the documents, not the tool list. Pull twenty of your hardest pages, the scanned ones, the nested tables, the two-column pages with footnotes, and run them through two or three candidates.

Then score the Markdown on four things: reading order, table structure, what happened to figures, and how much cleanup code you would need to ship. The comparison table near the top says what each tool returns; this is how to confirm it on your own pages. Our parser evaluation guide walks through that scoring, and the OCR-to-Markdown evaluation covers the metrics.

Final thoughts

The parser is the first model in your pipeline, and its mistakes are the ones you never see, because a shuffled table reads as fluent text. That is the argument for spending on this step. If your documents are hard and the output feeds software, LlamaParse is where we would start: the top ParseBench score, structure in every output format, extraction with citations, and a free plan big enough to test a real corpus. If the documents cannot leave your network, Docling is the safe open-source default and Marker the fast one. If the PDFs are clean, PyMuPDF4LLM will do in an afternoon. And if you are already on Azure, its Layout model's Markdown is the best of the cloud outputs. Whichever you choose, test on your worst twenty pages before you commit.

Frequently asked questions

What is the difference between PDF parsing, OCR and document understanding?

OCR turns an image of text into characters; it is the step scanned PDFs need and digital PDFs do not. PDF parsing extracts whatever the file holds, text, images, metadata, coordinates, and for a digital PDF needs no OCR at all. Document understanding is the layer on top: deciding that a block is a heading, that six aligned blocks are a table, that a two-column page reads down before across, and returning that structure as Markdown or JSON. PyMuPDF and pdfplumber stop at parsing. Docling, Marker, MinerU and the cloud Layout models add understanding from a layout model. LlamaParse adds orchestration and validation over several models. For retrieval or agents the understanding layer is the one that decides answer quality, because a flattened table chunks into nonsense that still embeds fine.

What is the best open-source PDF parser?

Docling for most teams: MIT license, the broadest input support, lossless JSON, and an active release cadence. Marker when throughput on a GPU matters and your company is under the $5 million license threshold. MinerU for scientific and technical PDFs with formulas and Chinese text. All three run offline. If you need an open-source parser that also handles charts and images with a vision-language model, our open-source OCR tools guide covers olmOCR and PaddleOCR-VL.

Is pdfplumber better than PyMuPDF, and where does pypdf fit?

They answer different questions. PyMuPDF is much faster and does more (rendering, OCR hooks, Markdown via PyMuPDF4LLM), so it is the default for bulk text extraction. pdfplumber exposes character coordinates and a visual debugger, so it wins when you are writing rules for a fixed layout and need to see why a table came out wrong. pypdf, the pure-Python library, is the one to reach for when you need to merge, split, rotate or encrypt PDFs with no compiled dependencies; its text extraction is basic and it has no OCR. None of the three understands layout, so for scanned or complex pages move up this list.

Can ChatGPT or Gemini parse a PDF?

Yes, and for a single document it is often good enough: upload the file and ask for Markdown, and a frontier model will transcribe tables and headings well. It does not scale into a pipeline. Page limits, cost per token, no bounding boxes, no confidence scores and occasional silent omissions of sections make a raw LLM a poor parser at volume, which is why every tool on this list that uses LLMs wraps them in a layout model and validation. Our post on why LLM APIs are not complete document parsers has the failure cases.

When should I choose a managed parser instead of self-hosting?

Self-host (Docling, Marker, MinerU, PyMuPDF) when documents cannot leave your network, when volume is steady enough that GPU hours beat per-page fees, or when you want to fine-tune. Use a managed parser when volume is spiky, when you want structured output without owning a model pipeline, or when the team maintaining it is one developer. If the documents are regulated, read where each vendor keeps them: the hosted tiers of LlamaParse, Azure, Google and Textract process pages on the vendor's side, Azure's containers and LlamaParse Enterprise's private VPC keep processing inside your own cloud, and the open-source parsers never send anything anywhere. Whatever you pick, the deciding cost is usually engineer-months on preprocessing and validation code, not the per-page fee.

Can these PDF parsers handle scanned PDFs, tables, handwriting and complex layouts?

Scans: every tool except pdfplumber can, but PyMuPDF only through Tesseract, and the AI parsers and cloud platforms do it natively. Tables: LlamaParse, Azure Layout, Google Layout Parser and Textract Tables rebuild structure including merged cells; Docling, Marker and MinerU do well on ruled and academic tables; the libraries lose structure on anything irregular. Handwriting: Textract, Google (200-plus languages) and Azure (nine languages) read it; LlamaParse handles it on the agentic tiers (our handwriting guide has the detail); the open-source parsers and libraries mostly do not. Complex layouts, meaning multi-column pages, sidebars, footnotes and figures, are where the agentic and layout-model parsers separate from the libraries. Our guide to the best AI for PDF table extraction goes tool by tool on tables alone.

What output format should I look for?

Markdown for anything an LLM will read, because headings, lists and tables survive and chunk cleanly. JSON for anything software will read, with field names, types and validation. The best parsers return both from one call, and add page numbers, bounding boxes, confidence and reading order so you can cite, highlight and debug. Treat the absence of coordinates as a real cost: without them, a wrong answer cannot be traced back to the page that caused it.
