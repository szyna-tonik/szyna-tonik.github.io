Classification is the first decision a document pipeline makes, and the one everything downstream inherits. Label a bank statement as an invoice and the extraction schema is wrong, the queue is wrong, and the reviewer who finally catches it has to send the file back to the start. A document classification platform makes that decision automatically: it reads each file, assigns a type, says how sure it is, and hands the result to whatever runs next.

This guide compares eight platforms on the four things that decide whether classification holds up in production: how you define the classes (plain-language rules, a trained model, or the vendor's fixed list), whether it splits mixed packets into separate documents, what comes back with each label (a confidence score, page ranges, a reason), and what it costs per thousand pages. The eight are LlamaParse, Google Document AI, Azure AI Document Intelligence, ABBYY Vantage, UiPath IXP, Hyperscience, Rossum and Nanonets. Prices are US list as of November 12, 2026.

Our pick is LlamaParse. It's the only platform here where you define classes as natural-language rules with no training set, get a confidence score and a written reason with every label, and can split a bundled file into segments with page ranges in the same pipeline.

Classification runs from 1 credit a page, and the result feeds extraction, with a 95.6% F1 score on ExtractBench, through the same API or MCP tools.

How we chose these eight

We started from what people ask AI assistants and each other when they need this: which tools automate extraction and classification together, which can classify a file and route it to the right extraction schema, and which handle packets where several documents arrive as one PDF. A platform made the list if it classifies documents as a product capability rather than a side effect, exposes that capability through an API, and is one that buyers compare by name.

LlamaParse is a LlamaIndex product. Its figures come from the published pricing and documentation and from ExtractBench, the public extraction benchmark LlamaIndex maintains, with the paper linked. The other platforms' figures are their own published claims, and we say so where one appears.

1. LlamaParse

LlamaParse treats classification as the routing step of an agentic document pipeline. You describe each class as a rule: a type name and a natural-language description of what belongs in it. No labeled training set, no model to retrain when a new document type shows up; you add a rule. Each file comes back with a predicted type, a confidence score from 0 to 1, and a step-by-step reason for the choice, which is the part reviewers and auditors ask for.

Bundled files go through Split, which classifies every page against your categories, detects where one document ends and the next begins, and returns segments with exact page numbers, a category and a confidence level. Pages that match nothing can land in a catch-all. From there the pipeline continues in the same place: extraction to a schema per document type, with a confidence score and page citation on every field, through REST, SDKs, or the hosted MCP server at mcp.llamaindex.ai that exposes Parse, Classify, Split, Extract and Index as tools.

What the platform gives you

  • Classify: natural-language rules; type, confidence and reasoning per file; Fast at 1 credit a page, Multimodal at 2.
  • Split: segments with page numbers, category and confidence; optional catch-all for unmatched pages; custom instructions to steer edge cases; 3 credits a page plus the parse.
  • Classify-then-extract in one pipeline: route each type to its own schema; extraction scores 95.6% F1 on ExtractBench.
  • Async jobs with webhooks, batches of up to 10,000 files on Pro and Enterprise, files up to 10,000 pages.

Best for

  • Teams that need classes defined this week, in plain English, without collecting hundreds of labeled samples.
  • Pipelines where the label chooses what happens next: extraction schema, queue, or approval path.
  • Agents and automations that call classify and split as tools and need a reason they can show.

Watch out for

  • Split is in beta and the API can change; pin your SDK version.
  • There's no built-in review screen. Confidence and reasoning come back through the API; the queue your reviewers work from is yours to build.
  • It's a hosted service with US and EU regions. Running in your own cloud is an Enterprise plan.

Integration and cost

  • Integration: REST API, SDKs in Python, TypeScript, Go and Java, a CLI, webhooks, and a hosted MCP server for Cursor, VS Code, Claude Code and Codex.
  • Data handling: SOC 2 Type II, HIPAA with a BAA, GDPR; files cached for 48 hours or not at all; no training on customer data.
  • Cost: pay as you go at $1.50 per 1,000 credits with 10,000 free credits a month; Pro at $500 a month brings the rate to $1.25. Classify costs 1 or 2 credits a page, so the free tier covers 5,000 to 10,000 pages of classification a month.

2. Google Document AI

Google Document AI handles classification with two processors. Custom Classifier assigns one label per document from a schema you define, and the current v1.5 model, built on Gemini 2.5 Flash, works zero-shot: no training required, with a confidence score per label. Custom Splitter is a separate processor that finds document boundaries in a combined file. Both are priced at $5 per 1,000 pages for the first million, then $3.

It fits a team already on Google Cloud that wants classification next to Document AI's extraction processors and a managed evaluation report (F1, precision and recall per label). Two caveats from the docs: the newer v1.6 release candidates on Gemini 3.1 don't return confidence scores yet, and labels are flat, so hierarchies have to be modeled as separate labels.

What the platform gives you

  • Zero-shot classification on v1.5, with optional fine-tuning when confidence calibration matters; Google recommends at least 10 documents per label if you train.
  • Per-label evaluation metrics in the console; a description field per label that works as a prompt to separate similar types.
  • Custom Splitter for packets, billed separately.

Best for

  • Google Cloud pipelines that classify, then extract with Form Parser or Custom Extractor, with results landing in BigQuery.
  • Teams that want a managed evaluation report before they switch a classifier on.

Watch out for

  • Classify plus split plus extract is three processors with three price lines; $5 + $5 + $30 per 1,000 pages before OCR.
  • No reasoning with the label, and no confidence on the v1.6 models.
  • Labels can't be deleted once a processor is trained, only disabled.

Integration and cost

  • Integration: REST and gRPC with Python, Java, Node, Go and .NET client libraries; batch from Cloud Storage; regional processing.
  • Cost: Custom Classifier and Custom Splitter $5 per 1,000 pages, $3 above a million; Enterprise Document OCR $1.50; Custom Extractor $30.

3. Azure AI Document Intelligence

Azure AI Document Intelligence takes the trained-model route. A custom classification model needs at least two classes and five sample documents per class, supports up to 1,000 classes, and can be retrained incrementally by adding samples or classes to an existing model. Each result carries a document type, a confidence score, and the page ranges that belong to it.

The feature that matters for mixed files is splitMode. By default the v4.0 API treats the whole file as one document; set it to auto and the service identifies each document and its page range, or to perPage to classify page by page. At $3 per 1,000 pages it's the cheapest hyperscaler classifier, and the one most buyers already have procurement for.

What the platform gives you

  • Trained classifiers from five samples per class; incremental training; up to 1,000 classes.
  • docType, confidence and page ranges per document; split modes none, perPage and auto.
  • A classifier that routes into prebuilt or custom extraction models in the same service.

Best for

  • Azure-centric teams with a stable set of document types and samples on hand.
  • Forms-heavy intake where the next step is a prebuilt model for invoices, receipts, IDs or tax forms.

Watch out for

  • Every new class needs samples and a training run, billed at $3 an hour; there's no zero-shot option.
  • Splitting is off by default; teams that forget splitMode get one label per file.
  • No written reason with the label, and no managed review queue; Studio is for labeling and testing.

Integration and cost

  • Integration: REST API with Python, .NET, Java and JavaScript SDKs; Document Intelligence Studio for labeling; data processed in the resource's region.
  • Cost: custom classification $3 per 1,000 pages; Read $1.50; prebuilt and Layout $10; custom extraction $30; 500 pages a month free on F0.

4. ABBYY Vantage

ABBYY Vantage is the enterprise capture platform on the list. Classification combines image features and text through multimodal models, covers structured, semi-structured and unstructured documents in more than 200 languages, and is trained from a few examples per class in a low-code designer. Splitting is built in: by blank pages or barcodes, with pretrained splitting models, or with a custom model trained to find document boundaries.

Each classified item carries a probability score, low-confidence results can go to a verification station, and reviewer corrections feed back into the model. The classified document then routes to the matching extraction skill. It fits a mailroom or shared-services operation where business analysts own the skills and reviewers are already in the loop; it's heavy for a developer who wants to send a file and get a label.

What the platform gives you

  • Multimodal classification across 200+ languages; three ways to split packets.
  • Probability score per result, optional human review, continuous learning from corrections.
  • Pretrained document skills for finance, logistics and other verticals; a marketplace of more.

Best for

  • Digital mailroom, accounts payable and logistics paperwork at enterprise volume.
  • Operations teams that configure skills without engineering.

Watch out for

  • Quote-only pricing and no self-serve tier to test with.
  • Setup is a project: skills, connectors and review stations all need configuring.
  • No API-only classification product for developers who don't want the platform.

Integration and cost

  • Integration: REST API; connectors for Power Automate, UiPath, Blue Prism and Automation Anywhere; intake from email, folders, scanners and mobile; output as JSON, CSV or XML.
  • Cost: quote only.

5. UiPath IXP

UiPath IXP is the document layer of the UiPath Platform, and Document Understanding gives it several classifiers to choose from: a Keyword Based Classifier, an Intelligent Keyword Classifier that also separates packages into individual documents, a Machine Learning Classifier, and a Generative Classifier. Results pass to Classification Station for human validation when confidence is low, then into the robots or agents that act on them.

It's the right shape when classification is one step in a process that already runs on UiPath: the label triggers an ERP entry, a claims update, or an agent built in Agent Builder. For a team that wants a classification endpoint and nothing else, it's a platform to adopt, not an API to call.

What the platform gives you

  • Keyword, intelligent keyword, machine learning and generative classifiers in one activity set; the intelligent keyword classifier splits packages.
  • Classification Station for human validation; validated results flow into robots and agents.
  • Automation Cloud, self-hosted Automation Suite, or hybrid deployment.

Best for

  • Accounts payable, claims and onboarding processes that already run on UiPath.
  • Teams that need the label to trigger work in legacy systems without APIs.

Watch out for

  • No public per-page price; licensing runs through the platform.
  • Standalone API use is a weak fit; the value is in the orchestration around it.
  • Platform skills are needed to build and maintain the classification workflows.

Integration and cost

  • Integration: native to UiPath robots, Agent Builder and Coded Agents; activities in Studio; Automation Cloud, Automation Suite or hybrid.
  • Cost: licensed through the UiPath Platform; quote.

6. Hyperscience

Hyperscience builds document processing from Blocks, with classification as one of the discrete functions alongside ingestion, extraction and validation, and human supervision woven through. Its claims are about outcomes rather than mechanics: customers "regularly achieve 99.5% accuracy and 98% automation," and 98% accuracy on handwriting and cursive in low-quality scans. Those are Hyperscience's figures on its customers' documents.

What sets it apart is where it runs: on premises, in a private tenant on AWS, Google or Azure, as SaaS, in air-gapped environments, and as a FedRAMP High authorized service. If the documents are handwritten government or healthcare forms and the deployment can't be public cloud, it's usually on the shortlist. Pricing is volume-based, with tiers from hundreds of thousands of pages a year up.

What the platform gives you

  • Classification, extraction and validation Blocks assembled into Flows, with an API and a Flows SDK.
  • QA and Supervision tasks that surface only the fields or characters below your SLA.
  • Deployment anywhere, including air-gapped and FedRAMP High.

Best for

  • High-volume handwritten and structured forms in government, healthcare and insurance.
  • Environments where the platform has to run inside the perimeter.

Watch out for

  • Volume-based pricing starts at hundreds of thousands of pages a year; it isn't built for a pilot.
  • Deployments are configuration projects measured in months, not days.
  • The accuracy figures are customer outcomes, not a public benchmark you can rerun.

Integration and cost

  • Integration: API-first with configurable integration Blocks; Flows SDK; on-prem, private cloud, SaaS or air-gapped.
  • Cost: volume-based quote; per-page cost falls with volume.

7. Rossum

Rossum, now part of Coupa, is transactional document automation with classification handled by its Aurora Document AI, which sorts incoming documents into the right queues before extraction and validation. It's built around the accounts payable and order-to-cash flows: invoices, purchase orders, delivery notes, with master-data matching, duplicate detection and an integrated mailbox on the Business plan and above.

Choose it when the documents are transactional and the team wants one product from inbox to ERP. Pricing starts at $18,000 a year on the Starter plan with unlimited seats and API access, on a one-year minimum, with a 14-day trial to test on your own files. Multi-document transactions arrive on the Ultimate plan.

What the platform gives you

  • Aurora Document AI routing documents to queues; a validation screen; 12 months of archive and search on Starter.
  • Master data matching, duplicate detection, custom functions and webhooks from Business up.
  • API and SFTP access; embeddable UI on Ultimate.

Best for

  • Accounts payable and order processing teams that want sorting, extraction and validation in one product.
  • Finance operations buying for the business rather than a developer stack.

Watch out for

  • Classification isn't sold as a standalone capability; it's the front of an AP workflow.
  • $18,000 a year minimum and annual contracts; no usage tier.
  • General document types outside transactional flows aren't the focus.

Integration and cost

  • Integration: REST API, SFTP, webhooks and custom functions; ERP connectors; preferred cloud location on Enterprise.
  • Cost: Starter from $18,000 a year; Business, Enterprise and Ultimate by quote.

8. Nanonets

Nanonets sells document workflows as blocks you chain: classification and validation blocks at $0.10 a run, extraction and generative blocks at $0.30, and formatting, routing and export blocks at $0.02. Classification AI arrives on the Growth plan; the free Starter tier includes $50 in credits for extraction and API access, then $100 a month for 100 credits.

It fits a mid-market team that wants to assemble classify-then-extract-then-export without engineering, and is willing to price per document rather than per page. Nanonets says a typical invoice workflow runs four to six blocks and lands under $2 a document end to end. Private cloud and on-prem deployment, SSO, HIPAA and SOC 2 are Enterprise-plan features.

What the platform gives you

  • Classification, validation, extraction and routing as chained blocks with per-run pricing.
  • Email intake, cloud storage connectors and API on every plan; ERP and database connectors on Growth.
  • Credits that are prepaid, shared across the team and don't expire.

Best for

  • Operations teams building classify-and-route workflows in a visual builder.
  • Moderate volumes where per-document pricing beats a platform license.

Watch out for

  • Classification isn't on the free tier; Growth pricing is by quote.
  • Per-run pricing compounds: a six-block workflow on 100,000 documents a month is a real bill.
  • Compliance features and private deployment are Enterprise-only.

Integration and cost

  • Integration: REST API, email and cloud storage intake, custom Python blocks and ERP connectors on Growth.
  • Cost: $0.10 per classification block run; $0.30 per extraction run; Starter free with $50 credits, then $100 a month; Growth and Enterprise by quote.

Classification inside the document pipeline

Which AI document processing tools automate extraction and classification?

All eight do both; the difference is whether the label can choose the extraction step on its own. LlamaParse classifies with natural-language rules and routes each type to its own extraction schema through the same API or MCP tools. Google Document AI pairs Custom Classifier with Form Parser or Custom Extractor. Azure AI Document Intelligence routes a classifier's output to prebuilt or custom extraction models, and ABBYY Vantage sends each classified document to the matching extraction skill.

UiPath IXP, Hyperscience, Rossum and Nanonets automate both as well, but inside a workflow product: the label moves the document to the next block, queue or robot, rather than returning to code you wrote.

Which tools combine extraction, classification and routing in document automation?

Routing is where the platforms split into two camps. Workflow platforms (UiPath IXP, Hyperscience, Rossum, Nanonets, ABBYY Vantage) route inside their own engines: a label sends the document to a queue, a robot, or an export block. API platforms leave routing to your code or your agent, which is more work and more control. LlamaParse sits in the second camp but closes most of the gap: classify, split and extract are tools an agent can call in sequence, so the routing logic lives in a few lines rather than a platform configuration.

How do you classify incoming files and route each to a different extraction schema?

The pattern is the same on every platform: classify first, branch on the label, extract with a schema per type, and send anything below your confidence threshold to a person. With LlamaParse that's a classify job with one rule per type ("invoice: a request for payment listing line items, totals and a due date"), a switch on the returned type, and an extraction call with the matching schema. Each field comes back with its own confidence and page citation.

Mixed packets add one step: run Split first, then classify or extract each segment by its page range. On Azure, the equivalent is a trained classifier with splitMode set to auto; on Google, Custom Splitter followed by Custom Classifier.

Zero-shot classification or a trained model: which should you use?

Zero-shot means you describe the classes and the platform classifies without a labeled set; LlamaParse's rules and Google's Custom Classifier v1.5 work this way. Trained models (Azure, ABBYY, UiPath's ML classifier, Hyperscience) learn from your samples and tend to win when the classes are narrow, stable and visually distinctive, at the cost of collecting samples and retraining when a type changes.

The practical split: start zero-shot to cover the long tail of document types quickly, and train only where a specific high-volume class needs tighter calibration. Either way, measure per class before you trust the threshold.

Test it on your own documents before you commit

Every platform on this list classifies a clean demo set well. The differences show up on your files: the scanned packet with three documents in it, the vendor whose invoices look like statements, the form that changed layout last quarter. Run the same test on each shortlisted platform before you sign anything. It takes a day and it's the only number that transfers to production.

Build the set

  • At least fifty files per class, pulled from real intake, and keep the ones people argued about. Those are the files that decide whether the threshold holds.
  • Hold out a third. Zero-shot platforms don't train, but you still want a set nobody tuned rules or descriptions against.
  • Include ten mixed packets if your intake has them. Score boundaries and page ranges separately from labels.

Score it

  • Precision and recall per class, not overall accuracy. One rare class failing silently is the usual production problem, and an overall figure hides it.
  • A confusion matrix, so you can see which classes bleed into each other and fix the rule or add the samples before launch.
  • Two counts that convert to money: files sent to review (your labor cost) and files classified wrong above the confidence threshold (your error cost). The second number is the one to minimize.

Here's the whole loop on LlamaParse: three rules in plain English, one classify call per file, a branch on the type, and extraction with the schema that matches. Anything under the threshold goes to a person.

from llama_cloud import LlamaCloud
 
client = LlamaCloud()  # reads LLAMA_CLOUD_API_KEY
 
RULES = [
    {"type": "invoice", "description": "A request for payment with an invoice number, bill-to block, line items and a total due."},
    {"type": "receipt", "description": "Proof of a completed purchase, usually one page, with merchant, items and amount paid."},
    {"type": "contract", "description": "An agreement between named parties with clauses, terms and signature blocks."},
]
SCHEMAS = {"invoice": INVOICE_SCHEMA, "receipt": RECEIPT_SCHEMA, "contract": CONTRACT_SCHEMA}
THRESHOLD = 0.85
 
def process(path):
    f = client.files.create(file=path, purpose="classify")
    job = client.classify.run(file_input=f.id, configuration={"rules": RULES})
    label, conf, why = job.result.type, job.result.confidence, job.result.reasoning
    if conf < THRESHOLD:
        return send_to_review(path, label, conf, why)
    extraction = client.extract.create(
        file_input=f.id,
        configuration={"data_schema": SCHEMAS[label], "extraction_target": "per_doc", "tier": "agentic"},
    )
    return label, extraction.id

Swap the three schemas for your own and point the review function at whatever queue your team already uses. If packets arrive as one file, run Split first and loop over the segments by page range instead of the file.

Final thoughts

The platform that classifies accurately on a demo set isn't always the one that holds up in production. What holds up is a platform where you can add a class without a training project, see why a document got its label, split the packets that arrive as one file, and route low-confidence results to a person without building the plumbing yourself.

LlamaParse is where we'd start: natural-language rules, confidence and reasoning on every label, Split for bundled files, and extraction in the same pipeline, from 1 credit a page. Azure and Google win inside their own clouds when you have samples or want zero-shot on Gemini. ABBYY, UiPath, Hyperscience, Rossum and Nanonets win when classification is the front door of a workflow that operations staff own.

Then prove it on your documents: fifty files per class including the ones people mislabel, a held-out set, precision and recall per class, and a count of how many files the platform flags for review versus how many it gets wrong with high confidence. That last number is the one that costs money.

What's the difference between OCR and document classification?

OCR turns an image of a page into text. Classification decides what kind of document the page belongs to and, in a good platform, where it should go next. OCR is usually an input to classification, not a substitute for it: a classifier can use the text, the layout, or both. Agentic document processing runs both inside one loop, so the classifier's label picks the parser settings and the extraction schema that follow.

Can these platforms classify multi-document PDFs and mixed packets?

Some can, and it's the feature to test first if your intake includes scans of whole folders. LlamaParse Split returns segments with page numbers, a category and a confidence level. Azure's custom classifier splits when splitMode is set to auto and returns page ranges per document. Google sells Custom Splitter as a separate processor. ABBYY splits by blank pages, barcodes, or a trained boundary model, and UiPath's Intelligent Keyword Classifier separates packages. Rossum and Nanonets work at the document level.

How should low-confidence classifications be handled?

Set a threshold per class based on the cost of a wrong route, not one global number. Below it, send the file to a review queue, a conservative default path, or an "other" class rather than guessing. Platforms with review built in (ABBYY, UiPath, Hyperscience, Rossum) give you that queue; API platforms give you the confidence score and leave the queue to you. LlamaParse adds the reasoning string, which is what makes a reviewer's decision fast.

Is a cloud API or a self-hosted classifier better?

A cloud API is faster to deploy and cheaper to run at low and medium volume; a self-hosted classifier is for data that can't leave your network. Among these eight, Hyperscience runs on premises and air-gapped, ABBYY and UiPath offer on-prem and hybrid, Nanonets offers private cloud on Enterprise, and LlamaParse runs in your own cloud on Enterprise. Google and Azure are cloud services, with Azure offering containers for Read and Layout but not for the classifier.

How do you measure a document classifier before you commit?

Fifty labeled files per class including the ambiguous ones, a held-out set, precision and recall per class, and two counts: files sent to review and files classified wrong above the threshold. The section above walks through it with a working example.
