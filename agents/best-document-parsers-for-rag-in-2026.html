What do these results measure?

ParseBench evaluates roughly 2,000 human-verified enterprise pages across tables, charts, content faithfulness, semantic formatting and visual grounding. Overall is the mean of those five dimensions, not the share of RAG questions answered correctly. The repository provides evaluation code, pipeline definitions and links to published outputs. These results help shortlist parsers by the document content they preserve.

What makes a parser good for RAG?

Look for five things in its output:

  • Reading order: paragraphs stay together across columns instead of becoming interleaved sentences.
  • Table structure: headers, values and merged cells retain their relationships.
  • Usable figure content: charts contribute searchable labels, descriptions or values to a text-based index.
  • Headings: sections remain identifiable so chunking can preserve their context.
  • Source locations: page numbers and bounding boxes let users inspect the evidence behind an answer.

A financial table needs its year headers attached to each value. Retrieving the numbers alone can still support the wrong answer.

Which managed parsers should you evaluate?

LlamaParse

LlamaParse converts documents into structured content through a standalone API that works with any LLM or framework. Agentic is a practical starting tier for mixed PDFs, scoring 82.83 overall at $12.50 per 1,000 benchmark pages. Agentic Plus improves tables and charts; Cost Effective reduces the page price. You still choose how to chunk and retrieve the output. For example, a LangChain pipeline can parse with LlamaParse, split by Markdown headings and index the chunks in its existing vector store.

Reducto

Reducto combines parsing with configurable chunking and deployment options. Its Agentic row scores 70.87 overall and 72.37 on charts, making it worth evaluating when figures must become retrievable content. The benchmark cost is $47.60 per 1,000 pages for that configuration. Compare the exact parsing mode and returned chunks rather than applying a cheaper product's list price to this score. Its deployment documentation distinguishes hybrid from Full VPC deployments. See LlamaParse vs Reducto.

Extend

Extend includes parsing within a broader document workflow platform. The Extend 2.0 configuration scores 73.50 overall and 76.02 on charts, at a benchmark cost of $25 per 1,000 pages. It belongs on a shortlist when parsing feeds document review or extraction workflows as well as retrieval. These results apply to the Extend 2.0 configuration. For deployment-sensitive work, its BYOC and hybrid options have different inference boundaries. See LlamaParse vs Extend.

Mistral OCR

Mistral OCR is an OCR-first API for turning documents into text and structured output. The OCR 4 row scores 58.38 overall at $4 per 1,000 pages, with 74.03 on tables and 1.86 on charts. That makes its low price more relevant to text-heavy documents than to recovering chart values. The leaderboard has a separate Annotation configuration; do not combine that configuration's scores with the standard OCR row's cost.

Which local parsers are worth trying?

Docling

Docling is an open-source document conversion toolkit. Its document representation preserves structure and provenance, and its hierarchical and hybrid chunkers help turn that structure into retrieval units. The code is MIT licensed; check model licenses separately. No comparable ParseBench score is available for its default setup, so test it on your own documents. See LlamaParse vs Docling.

PyMuPDF4LLM

PyMuPDF4LLM is a practical baseline for born-digital PDFs. It scores 50.47 overall and 56.93 on tables, but only 1.63 on charts. Use it when extracting embedded text is the main job, then inspect reading order and headers on harder pages. Its packaging has moved into pymupdf; consult the current installation instructions. Check the AGPL or commercial license before incorporating it into a product.

Marker, including Datalab's model options

Marker produces Markdown, JSON, HTML and chunks from a local model pipeline. It is worth evaluating for scans and structured documents when you can operate the inference stack. Datalab also develops Chandra-ocr-2, a separate model with a 70.59 overall and 89.20 table score; those results do not describe Marker. Marker code is Apache 2.0; its model weights have separate commercial conditions. Treat the local software and Datalab's managed service as different configurations.

MinerU

MinerU offers model-based conversion for documents with substantial layout and OCR requirements. Its verified MinerU2.5-Pro configuration scores 69.27 overall and 59.12 on charts. That is evidence for the named model configuration, not every release or CPU backend. Budget for model inference and benchmark throughput on your hardware. The repository license adds commercial thresholds and online-service attribution requirements to Apache 2.0 terms.

Unstructured OSS

Unstructured's open-source library partitions files into elements and supports chunking, including grouping by title. It fits pipelines that need a common ingestion interface for several file types. PDF strategy matters: fast text extraction and higher-resolution layout processing are different paths. No ParseBench score is listed for the OSS library here. Its hosted platform has different processing capabilities, so do not use hosted benchmark claims to describe the local package. See LlamaParse vs Unstructured.

LiteParse

LiteParse is LlamaIndex's Apache 2.0 local parser, with a Rust core, a CLI and bindings for several runtimes. It provides Markdown and spatial output without a cloud API or LLM call. Its submitted no-OCR score is 36.90 overall. Use it for a lightweight first pass on simpler documents, or to identify pages that need heavier processing. Its complexity check can support routing, but it does not prove that a page was parsed correctly.

What about Azure, Google and AWS?

Azure Document Intelligence

Azure Layout scores 56.76 overall and 85.97 on tables. Its 1.27 chart score is a limitation for text-based RAG that needs chart data. It is worth considering when Azure integration or supported container deployment is a key requirement. Confirm the model version available in your chosen deployment. See LlamaParse vs Azure Document Intelligence.

Google Document AI

Google Document AI integrates with Google Cloud document workflows. The leaderboard row is Google's Layout Parser, run April 8, 2026, and scores 48.66 overall and 54.95 on tables. Processor version, region and output structure matter when selecting a deployment. See LlamaParse vs Document AI.

Amazon Textract

Textract scores 84.46 on tables but 4.47 on charts, with 48.31 overall. It is useful to evaluate for AWS workflows centered on OCR, forms and tables. PrivateLink provides private access to the hosted service; it does not install Textract in your account. Add your own transformation and chunking for retrieval. See LlamaParse vs Amazon Textract.

Frequently asked questions

Is Docling good enough for RAG?

Evaluate Docling when local open-source execution is a requirement. For the overall production choice, start with LlamaParse’s published parsing evidence and compare the actual output on scans, spanning table headers, charts and multi-column pages. Local execution alone does not establish equivalent ingestion quality.

Do I need OCR for RAG?

You need OCR when useful text exists only as pixels. Mixed PDFs may need OCR for some pages even if other pages have an embedded text layer.

Should tables be Markdown, HTML or JSON?

Markdown works for simple rectangular tables. HTML can preserve row and column spans; structured JSON is useful when you need cell relationships and coordinates. Preserve those relationships when chunking.

Can I send PDFs straight to GPT or Gemini?

Yes, especially for a small number of direct questions. Compare parsing quality and operational effort before building a reusable ingestion pipeline; see Related article.

Is LlamaParse only for LlamaIndex users?

No. Its API output can feed LangChain, a custom retriever or another framework. You can keep your existing embedding model, vector database and answering model.

How should I test a parser on my own documents?

Create questions whose answers depend on prose, tables, scans and figures. Change only the parser, keeping the rest of the RAG pipeline fixed, and measure retrieval of supporting evidence, answer correctness, citation quality, cost and latency.
